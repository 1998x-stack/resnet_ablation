## 1. Paper evidence: ar5iv reading notes

These are short **paraphrases with section pointers**, not copied article passages or experimental results of this repository.

| Source | Relevant passage | Implication for this repository |
| --- | --- | --- |
| [He et al., *Deep Residual Learning for Image Recognition*](https://ar5iv.labs.arxiv.org/html/1512.03385) | §3.2, Eq. (1)–(2): the residual branch is added to an identity shortcut, with projection if dimensions mismatch. §3.3 distinguishes zero-padded identity (A), projection for dimension changes (B) and projection for **all** shortcuts (C). §4.2 describes CIFAR networks with depth `6n+2`. | Report exact shortcut semantics and residual block count; when comparing plain and residual nets, control width, depth and training recipe. The current repository **does not provide a plain-network baseline**. |
| [He et al., *Identity Mappings in Deep Residual Networks*](https://ar5iv.labs.arxiv.org/html/1603.05027) | §4.1: moving BN and ReLU ahead of weight layers and keeping the post-addition path as identity defines full pre-activation units. | Current `BasicBlock`/`Bottleneck` apply ReLU after addition; do **not** label them pre-activation ResNet. Introduce a separate architecture and dedicated tests if studying pre-activation. |
| [Hu et al., *Squeeze-and-Excitation Networks*](https://ar5iv.labs.arxiv.org/html/1709.01507) | §III: spatial global-average pooling generates channel descriptors; two learned transforms and sigmoid provide channel-wise reweighting. | `SEModule` follows this overall design; compare its parameter and compute overhead at fixed `se_ratio`, backbone and training recipe. |
| [Wang et al., *ECA-Net*](https://ar5iv.labs.arxiv.org/html/1910.03151) | §3.2: local cross-channel interaction through 1-D convolution avoids SE's channel bottleneck, with kernel size adapted to channel count. | `ECAModule` uses GAP + Conv1d + sigmoid; verify its adaptive kernel-size choices against the intended implementation before claiming exact paper reproduction. |

**Attribution boundary:** Any metrics reported by the four papers concern their own experimental settings, not results measured in this repository. The repository's ImageNet bottleneck places stride in the 3×3 convolution (the commonly named v1.5 layout); distinguish this from exact original-paper reproduction.

## 3. Experiment matrix and interpretation

**Do not claim causal effects from the supplied multi-factor examples.** At minimum, prepare these matched comparisons, retaining identical seeds, data/split, number of epochs, batch size, optimizer, LR schedule, transforms, and evaluation procedure within each pair:

1. CIFAR-10 ResNet-20, `attention=none` vs `attention=se`, all other parameters fixed.
2. CIFAR-10 ResNet-20, `attention=none` vs `attention=eca`, all other parameters fixed.
3. CIFAR-10 ResNet-56, shortcut A vs B, with parameter-count difference reported (projection adds parameters).
4. CIFAR-10 ResNet-20, `drop_path_rate=0` vs one positive, fixed rate and same training recipe; use the **corrected schedule** in both comparisons.
5. ImageNet ResNet-50, standard vs deep stem; separately compare `proj` vs `avgproj` with stem fixed. Do not change both in a one-factor comparison.

For each condition, keep a fixed set of multiple independent seeds and separate run directories. Report per-seed results, mean and standard deviation, parameters, compute and actual runtime; do not assert an accuracy gain or a paper-reproduction result without running the experiments. CIFAR test data should not be repeatedly used to select hyperparameters: use a separate training/validation split and evaluate the test set after selection. Existing `build_cifar10`/`build_cifar100` return training and test loaders, so the current training script evaluates on **test**, despite calling the loader `val_loader`. This is an explicit methodological limitation until a real validation split is added.

## 4. Verification plan and acceptance gates

### Gate A — unit and architecture smoke tests (no dataset download)

```bash
python3 -m pip install -e .
python3 -m pytest -q
python3 -m compileall -q resnet_ablation scripts tests
```

Assert CIFAR-20/56/110 residual block counts (`9/27/54`), DropPath schedule monotonicity, first probability `0` and last probability equal to the configured maximum, valid forward shape, finite backward gradients and model/optimizer state round trips. These tests were **added, not executed**, as part of PR #1.

### Gate B — training and recovery invariants

Use a small deterministic in-memory dataset and CPU-first model. Compare uninterrupted training to an interrupted/resumed run under the **same input order and restored RNG state**: no repeated/missing epochs, identical per-epoch LR sequence, matching model/optimizer/scheduler/scaler states and compatible recorded metrics. Run a separate case with `val_interval > 1` to check latest checkpoint after every epoch and best checkpoint only on validated improvement. Test checkpoint writing under simulated interruption and confirm readers never observe a partial final file.

### Gate C — scientific reproducibility and hardware

Only after A/B pass, evaluate repeated seeds with fixed data splits and logged dependencies, hardware, code revision, transforms and checkpoint hash. Run supported GPU and CPU modes separately. Record actual accuracy, memory, throughput, runtime, parameter counts and compute; do not fabricate benchmarks or equate comparisons across changed hardware, schedules or datasets.
