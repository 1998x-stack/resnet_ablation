# ResNet ablation code review — 2026-09-21

## Scope and evidence

Reviewed the repository's CIFAR/ImageNet architectures, residual blocks, configuration, trainer, training entry point, scheduler, augmentation/data pipeline and existing test inventory. This review distinguishes defects confirmed by static inspection from hypotheses requiring runtime verification. Full dataset training, ImageNet accuracy and reproduction of published paper numbers have **not** been performed.

## Literature and experiment design

- He et al., *Deep Residual Learning for Image Recognition* (2015): https://ar5iv.labs.arxiv.org/html/1512.03385 — residual-vs-plain network comparisons, CIFAR 6n+2 layout and identity vs projection shortcuts.
- He et al., *Identity Mappings in Deep Residual Networks* (2016): https://ar5iv.labs.arxiv.org/html/1603.05027 — pre-activation is a distinct experimental architecture, not interchangeable with the repository's post-activation blocks.
- Hu et al., *Squeeze-and-Excitation Networks* (2017): https://ar5iv.labs.arxiv.org/html/1709.01507 — attention changes parameter count; report it along with accuracy.
- Wang et al., *ECA-Net* (2019): https://ar5iv.labs.arxiv.org/html/1910.03151 — compare attention under the same data and training recipe.

For valid one-factor-at-a-time comparisons, fix dataset/split, input preprocessing, seed set, optimizer, LR schedule, number of epochs, batch size and evaluation policy. Report the mean and dispersion over repeated seeds, train and validation metrics, parameter count, compute, and runtime. Treat CIFAR's test set as a final evaluation set rather than repeatedly tuning on it.

## Findings

### Fixed by accompanying code change

1. CIFAR DropPath erroneously used `3 * (2 * n)` positions for `3 * n` BasicBlocks; the final residual block received only about half the requested rate. This branch changes the schedule to count actual blocks and adds regression tests at depths 20, 56 and 110.
2. CIFAR depth/width/rate validation now produces explicit input errors rather than silently constructing a malformed architecture.

### Follow-up work (not claimed as fixed)

1. `scripts/train.py` sets `start_epoch` to the completed checkpoint epoch returned by `Trainer.load`, replaying that epoch; change the script's loop start to `loaded_epoch + 1`, with a backward-compatible regression test.
2. The script saves only on validation epochs; for `val_interval > 1`, checkpoint the latest training state every epoch and retain best selection only after validation.
3. Capture LR **before** training and log that LR, rather than logging the post-`sched.step()` LR as the just-completed epoch's value.
4. `scheduler.py` uses cosine `T_max=total_epochs` even after a warmup stage; test and define the intended post-warmup horizon, as well as resume-vs-uninterrupted LR traces.
5. Save Python, NumPy, PyTorch and CUDA random-generator states together with model/optimizer/scheduler/scaler state for reproducible resumed runs. Use atomic temporary-file replacement for checkpoints and review safe-loading requirements for untrusted files.
6. The CIFAR-10 and CIFAR-100 pipelines use the same normalization constants. Check dataset-specific statistics and compare against the experimental recipe rather than changing historical baselines silently.
7. `BasicBlock` aliases shortcut B and C; the original paper treats projection-shortcut options differently. Do not label them as separate ablation conditions until the intended distinction is implemented and tested.
8. `Bottleneck` uses stride in its 3x3 convolution (a common ResNet-v1.5 variant). Disclose this when comparing against exact original-paper architectures.
9. With Mixup/CutMix, training accuracy is currently computed against *pre-mix hard labels*, so it is not a conventional accuracy statistic. Label the metric accordingly or report separate unaugmented accuracy.
10. `Config.validate()` checks field names and enums but does not enforce positive epochs/batch size, nonnegative augmentation strengths, data-model class-count consistency or feasible top-k bounds. Add explicit validation before expensive runs.

## Acceptance gates for the next iteration

- Run unit tests on supported CPU/accelerator platforms (no dataset downloads required for smoke tests).
- Confirm CIFAR-20/56/110 forward shape, expected residual block count and DropPath schedule endpoints.
- Record uninterrupted vs interrupted-and-resumed LR traces, epoch sequences and final model weights under fixed data order and RNG state.
- Check per-epoch metric rows and checkpoint consistency when validation interval is greater than one.
- Execute an actual repeated-seed benchmark **only after** the correctness checks pass. Do not claim publication-level reproducibility from unit tests alone.
